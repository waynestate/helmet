# MAINTAINING: checking the straps

How to build, test, release and keep HELMET current. HELMET is the runtime baseline every stack app wears: security
headers, CSP with nonces, session hardening, trusted proxies, a `/up` health check, optional `/metrics` and
structured logs. A helmet only works if somebody checks the straps, so this is that somebody's guide.

## What HELMET is and what it depends on

- `waynestate/helmet` on Packagist. Framework-free core (PSR-15 middleware and a raw-PHP `helmet_boot()`), with a
  Laravel adapter (service provider and `config/helmet.php`).
- Platform presets (for example `citadel`) set the proxy and HTTPS assumptions for where the app runs.
- Runtime dependencies: `paragonie/csp-builder`, `monolog/monolog`, `promphp/prometheus_client_php`,
  `symfony/http-foundation`, PSR interfaces. No other stack package at runtime. Dev: PHPUnit, Pint and PHPStan
  (presets from Pinstripe, `^0.1.4`), Orchestra Testbench, `nyholm/psr7`.
- **Its policy input:** if `HELMET_POLICY_PATH` points at a CREED `policy.json`, HELMET can warn about an unsupported
  runtime. A missing or unreadable file means no warning, silently. Tests use `tests/fixtures/policy.json`.
- **Who uses it:** apps generated by Sourdough, WELD, and every stack front page (through each repo's `deploy/` layer).

## Where it lives

Development happens on git.wayne.edu (the canonical repo, [enterprise-apps/helmet](https://git.wayne.edu/enterprise-apps/helmet); clone over SSH as `git@git.wayne.edu:enterprise-apps/helmet.git`, or HTTPS as `https://git.wayne.edu/enterprise-apps/helmet.git`). The GitHub repository is a read-only push mirror (`main` and tags are copied automatically). Changes, issues and merge requests go to git.wayne.edu; nobody pushes to the mirror. Tags are made on git.wayne.edu, by the maintainer, with an approver.

## Build and test

| Task | Command |
|---|---|
| Install | `composer install` |
| All checks (what CI runs) | `composer ci` |
| Only the tests | `composer test` |
| Fix code style | `composer fix` |

With only Docker (the same lines work in PowerShell and sh):

```
docker run --rm -v "${PWD}:/app" -w /app composer:2.11.1@sha256:8de2184c6de224f4689e8f80ed5f5edaf0030b6b8b7839a22a2bcb6722ac87d0 sh -c "composer install --no-interaction && composer ci"
docker run --rm -v "${PWD}:/app" -w /app php:8.3-cli vendor/bin/phpunit
docker run --rm -v "${PWD}:/app" -w /app php:8.5-cli vendor/bin/phpunit
```

`composer ci` runs `composer validate --strict`, the tests, Pint, PHPStan, the agent-ready check (`site:agent-ready-check`),
the docs site check (`docs:check`) and `composer audit`. On Windows, if tests
fail oddly after a Docker install, delete `vendor/` and install again.

## CI

- **GitLab:** Preflight's `php-test` (PHP 8.3, 8.4, 8.5), `composer-audit`, `proctor`, `secret-detection` and `a11y`
  components (all pinned to Preflight 0.4.0), plus HELMET's own `wayneui-copies` and `composer-ci` jobs.
- **GitHub:** `.github/workflows/ci.yml` calls Preflight's reusable workflow with `composer ci`.
- Green means `composer ci` passed on all three PHP versions on both.

## Changing it safely

- Headers are a contract with every app. Tightening a default (a stricter CSP, a new header) can break pages that
  load inline scripts or third-party assets, so say so in the CHANGELOG and prefer a setting with the safe default.
- The trusted-proxy list decides whether `X-Forwarded-*` headers are believed. Changes there are security changes:
  test them and get a second reviewer.
- `/metrics` is off by default and gated; keep it that way.
- Browser behavior changes over time; recheck headers against current guidance (OWASP, MDN) when you touch them.

## Releasing

1. Move the lines under `## Unreleased` in `CHANGELOG.md` to a new `## X.Y.Z (YYYY-MM-DD)` heading, and leave an
   empty `## Unreleased` above it.
2. `composer ci` green locally, then on both pipelines for that commit.
3. Run a secrets scan of the history and check that nothing internal (server names, people, IDs) is in the tree.
4. Tag `X.Y.Z` (no `v`) on git.wayne.edu. The mirror carries the tag to GitHub, and Packagist picks it up from there.
5. A release needs a maintainer's approval. Never move or delete a published tag.
6. Then bump `waynestate/helmet` where the stack pins it: WELD, Sourdough's templates, and each repo's
   `deploy/composer.lock`.

## The front page

`site/` is the static front page, for `https://helmet.apps.wayne.edu/` on Citadel, served (fittingly) behind HELMET by
