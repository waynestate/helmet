What the film caught

On the 17 apps whose own rewrite sends /up into helmet_boot(), the health answer goes out before X-Powered-By is stripped, so /up still says which PHP it runs. That is a one-line fix, queued for the next tag with a test. Three apps set a session cookie on their front page, and all three got Secure, HttpOnly and SameSite from HELMET's session settings. The libraries (6), the starter template and Citadel's six PHP test pages ran too: all passed, and two test pages that need their own config to render still wore every header.

Third quarter · Run the play

Run it on your own app

Install HELMET, call helmet_boot() at the top of the front controller, and read your own headers.

Install

composer require waynestate/helmet

First lines of public/index.php

<?php require __DIR__ . '/../vendor/autoload.php'; $helmet = Waynestate\Helmet\helmet_boot(['preset' => 'citadel']);

Read the headers (behind your HTTPS proxy)

curl -sI https://your-app.example/ && curl -s https://your-app.example/up

The proof rig did the same with auto_prepend_file so no app file had to change, trusted only the loopback proxy, and sent X-Forwarded-Proto: https the way a platform proxy does. Each boot is logged as one line (tool commit, anonymous unit id, app commit, command, exit code, duration, outcome) in the stack's internal record.

Fourth quarter · The fine print

What this does not prove

  • It proves the headers go out, not that each app's pages work under the CSP. An app with inline scripts needs their nonces before the policy stops blocking them; that is the app's work, and the CSP report endpoint is how to find it.
  • No app reached a real database, Oracle, CAS or any Wayne State service. Most front pages rendered without one; deeper pages that need one were not visited.
  • It ran on PHP 8.4 only, the platform's current image. An app whose code would not parse on 8.4 still gets HELMET's answer at /up and its headers, because HELMET runs before the app does; whether the app itself works on 8.4 is BOOSTER's question.
  • HTTPS was simulated through a trusted proxy header over loopback. The one app that redirects to HTTPS in its own .htaccess never let PHP run, so it counts as not applicable, not as a pass.
  • It covers the raw PHP path. The Laravel middleware has its own tests; a Laravel boot proof waits for apps whose dependencies install without Wayne State's private registries.
